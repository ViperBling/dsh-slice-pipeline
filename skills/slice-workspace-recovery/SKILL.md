# slice-workspace-recovery —— 工作区恢复

## 何时使用 / 不负责

- 用于：在原仓库验证前记录基线快照、验证后安全回退并核对工作区、处理 `reverted` 异常或怀疑工作区被改脏。
- 不负责：产出 patch（交给 `slice-patch-delivery`）；未经用户确认的破坏性清理。

## 入口步骤

1. 读取正文末尾 `## 当前模块配置` 中本模块规范的绝对路径（注入块「规范文件」行），先 read 规范再动手。
2. 该路径标为「（缺失）」或读取失败时：报告该确切路径并询问用户，不自行补规则、不换别的文件。
3. 开工前记录基线：状态快照加内容级快照；脏基线先按规范暂存，再回到 HEAD。
4. 验证后按基线是否干净选择回退路径，完成后与基线逐项比对，确认完全一致。
5. 派发子代理时，按注入块中「派发角色」行的 provider/model 路由；加载本 Skill 本身不切换当前会话模型。

## 与其他模块

- `slice-patch-delivery`：它产出 patch 与薄文档，本模块负责验证场地、基线与回退。
- `slice-review`：审查报告落盘与闭环同步由主会话负责，本模块不产出审查结论。
- 只按注入的绝对路径读取；读不到就报告该路径，禁止 `find /` 或扫描盘符。
