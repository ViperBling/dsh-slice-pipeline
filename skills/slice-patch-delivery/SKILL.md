# slice-patch-delivery —— 补丁交付

## 何时使用 / 不负责

- 用于：写代码、产出或修复 patch、写薄文档、交付三件套、按用户要求落盘改动。
- 不负责：给出审查结论；在原仓库验证与回退交给 `slice-workspace-recovery`。

## 入口步骤

1. 读取正文末尾 `## 当前模块配置` 中本模块规范的绝对路径（注入块「规范文件」行）；有「薄文档模板」行时一并读取，先 read 再动手。
2. 该路径标为「（缺失）」或读取失败时：报告该确切路径并询问用户，不自行补规则、不换别的文件。
3. 按规范产出 raw patch 与薄文档三件套：先过编译验证、按规范「2. 最终 patch 的代码放置与 include 顺序」自检与机械预检，再交审查。
4. 需要在原仓库验证或回退时，按注入块中「相关模块」行给出的绝对路径加载 `slice-workspace-recovery`。
5. 审查由 `slice-review` 负责；派发子代理时按注入块中「派发角色」行的 provider/model 路由，加载本 Skill 本身不切换当前会话模型。

## 与其他模块

- `slice-workspace-recovery`：在原仓库编译验证前记录基线、验证后安全回退并核对。
- `slice-review`：patch 与薄文档的审查；修复意见确认后回到本模块生成修复 patch。
- `slice-planning`：本模块按它产出的 Slice brief 实现，不自行改接口契约或切片边界。
- 闭环时立即同步主计划与索引，不留到用户落盘时手工同步。
- 只按注入的绝对路径读取；读不到就报告该路径，禁止 `find /` 或扫描盘符。
