# slice-review —— 审查

## 何时使用 / 不负责

- 用于：代码、Diff、设计或计划评审；派发审查子代理；处理审查意见与审查-修复闭环。
- 不负责：修改代码；修复交给 `slice-patch-delivery`（修复回生成方，不回审查方）。

## 入口步骤

1. 读取正文末尾 `## 当前模块配置` 的两份规范绝对路径：
   - **审查运行时规范**（`review-standard.md`）：审查判据；派发 reviewer 时让子代理只读这一份。
   - **审查派发规范**（`review-dispatch.md`）：输入纪律、模型分层、工具约定、设计原则与修复闭环；Lead/人工读这一份。
2. 任一规范标为「（缺失）」或读取失败时：报告该确切路径并询问用户，不自行补规则、不换别的文件。
3. 用户点名模型时，读取注入块中「人工派发约定」行给出的绝对路径，按其中的本机偏好执行。
4. 派发审查子代理时，按注入块中「派发角色」行的 provider/model 路由；加载本 Skill 本身不切换当前会话模型。任务书只让子代理读运行时规范，不读派发规范。
5. 闭环时把修复交回生成方，并按派发规范重新验证与复审。

## 与其他模块

- `slice-patch-delivery`：按本模块结论生成修复 patch；修复必须重新编译并重新生成 patch。
- `slice-planning`：规划与 brief（planReview / briefReview 已归档，不启用的评审仅在用户明确要求时人工派发）。
- `slice-workspace-recovery`：审查前的编译验证与工作区回退由它负责。
- 只按注入的绝对路径读取；读不到就报告该路径，禁止 `find /` 或扫描盘符。
