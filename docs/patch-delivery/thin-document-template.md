# Slice 薄文档模板（v2 默认）

> 适用范围：写 Slice 薄文档时；由 `slice-patch-delivery` Skill 加载。
> 规范内容直接在本文件中维护；模板与模板纪律保持原样。

```markdown
# <项目> Slice <N> —— <标题> v<版本>（编译验证版）

> 基线：HEAD = <commit>；事实源：`<任务名>.patch`；主计划：`<plan>.md` 的 S<N> 小节；
> 审查：`<任务名>-review.md`；本文档不含完整 diff 与自评表。

## 1. 目标与范围
（≤8 行；本片做什么/不做什么；对应主计划编号）

## 2. 接口与行为变更
（只列外部可见：签名、语义、资源生命周期、错误路径、版本号/缓存失效）

## 3. 关键设计说明
（≤20 行；为什么这么改、取舍、拒绝的替代方案）

## 4. 验证记录
（命令 + exit code + ctest 结果 + 定向测试；未验证项明确标注）

## 5. 验收与未达项
- [ ] 可勾选清单
- 未达成项 + 原因 + 移交哪个 Slice

## 6. 回滚方案
（如何回到上一基线；是否需 reconfigure/rebuild/re-cook）

## 7. 决策与主计划同步
（本片新增决策 + 本次闭环已经回写主计划的条目）

## 8. 残余风险 / 推迟事项
（接受的风险、未覆盖边界、测试缺口）

## 9. 审查处置摘要
（引用 `<任务名>-review.md`；只放结论：采纳/驳回/接受风险的编号）

## 10. 变更历史
（≤3 行版本摘要；旧 patch 与旧文档一律进 `archive/`）
```

模板纪律：

- 文字按 `docs/shared/plain-language.md` 写：读者假设、先结论后依据、术语首次出现解释、不写流程黑话；模板不复制规则。
- 涉及热路径的改动：验证记录写性能测量方式 + 结果；未测量写「未测量 + 原因」。
- **diff 只存在于 `.patch`**；薄文档引用它，不复制它。
- **不写** R0-RN 全量自评、十维自评、A-F 原则自评；这些是生成期内部检查项，写进文档只会增加 Token 并锚定审查模型。
- 审查报告独立存放，不塞进薄文档；历史修订进 `archive/`，不用附录 A/B 形式堆在活文档里。
- 薄文档目标 ≤150 行；超了说明范围或说明写多了，优先砍说明而不是砍 diff。
